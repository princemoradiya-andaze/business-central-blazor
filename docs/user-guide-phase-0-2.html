Getting started and using the application

A practical walkthrough of the foundation and core financial features delivered in Phases 0, 1, and 2.

User guide | 12 October 2026
For the current application before Phase 3

Start here

What this guide covers

Follow the everyday user journey: sign in, enter the right company workspace, configure the financial foundation, record activity, and review the results.

Phase 0 - Foundation

Application and database foundation, tenant/company structure, and the initial schema. A system administrator prepares the environment and provisions access.

Phase 1 - Access and workspace

Administrator-managed sign-in, company membership and selection, an authenticated application shell, and a generic company-scoped Workspace notes example.

Phase 2 - Core financials

Chart of Accounts, dimensions, accounting periods, general journals, posted ledger inquiry, account activity and trial balance, manual tax setup, company base currency, bank accounts, and manual statement reconciliation.

Important: This is an independently implemented ERP application inspired by common accounting workflows. It is not Microsoft Dynamics 365 Business Central, and it does not include Microsoft code or assets.

Before you begin

  • Your administrator must provide your sign-in account and assign membership in at least one active tenant/company. There is no public self-registration.
  • For the locally tested application, open http://localhost:5212 while the local web app is running. Your organization's deployed address may be different.
  • Use the correct company before creating or reviewing financial data. Financial records are scoped to the active company.
  • Use your organization's accounting policies for account setup, dates, tax treatment, and reconciliation. The examples in this guide are illustrative, not accounting advice.

At a glance

Access and navigation

Sign in and choose a company

  1. Open the application. Go to your organization's application address (for the local test environment, http://localhost:5212).
  2. Sign in. Enter the email address and password supplied by your administrator, then choose Sign in. If you need access or cannot sign in, contact the administrator. Accounts can be locked temporarily after repeated failed attempts.
  3. Choose the workspace. If you have more than one eligible company, choose one from Select a company, then choose Continue to company. With exactly one eligible company, the app can select it automatically.
  4. Confirm the active company. The navigation area displays Company: Name (Code). Choose Select company there whenever you need to switch to another company.
  5. Sign out when finished. Use Sign out in the navigation.
No company access? The application cannot grant membership to itself. Ask an administrator to confirm that your account has both tenant and company membership and that the company is active.

Company setup

Prepare the financial workspace

Set up the essentials before entering journals or creating bank accounts. Menu labels below are shown as they appear in the application.

  1. Set company base currency first. From the top header choose Company workspace settings. If the needed currency is absent, add it to the shared catalog using a three-letter code, name, and minor-unit precision (0-4). Select it as this company's base currency and choose Save base currency. Currency catalog entries are shared; the base-currency setting belongs to the active company.
  2. Create posting accounts. Open Chart of Accounts > New account. Give each account a unique number and name, choose its category and type, and configure whether direct posting is allowed or the account is blocked. Use posting accounts for journal lines. Plan account categories carefully - tax mappings and bank-account mappings require eligible accounts of the appropriate category.
  3. Define the accounting periods. Open Accounting periods, enter a name, start date, and end date, and choose Create period. Periods must not overlap. Keep the relevant period open and not date-locked while you enter and post transactions. Closed/locked periods prevent posting for dates they cover.
  4. Set up dimensions when you need analysis tags. Open Dimensions > New dimension; then open the dimension and use New value to add its allowed values. For example, a Department dimension might have values such as SALES or OPERATIONS. Select dimension/value pairs on journal lines.
  5. Set up tax mappings if required. Open Tax setup. Create an unblocked tax code with eligible liability and recoverable posting accounts, then add a rate and its effective-from/through dates. Rates for the same code must not overlap.
  6. Create bank accounts after base currency and G/L setup. Open Banking & reconciliation > choose a dedicated, unblocked, directly-postable Asset posting account, provide a unique bank code/name and optional ordinary account identifier, then choose Save bank account.
Currency setting is an early setup decision. The bank workflow uses the company's base currency and does not support foreign exchange. Changing base currency is blocked after the company has dependent journal, bank, ledger, or currency-rate activity.

Account numbers, period dates, tax treatment, and dimensions should follow your organization's chart-of-accounts and accounting policies. The app validates posting eligibility and company boundaries, but it does not determine whether your accounting policy is correct.

Journals and ledger

Enter, post, and correct journal activity

  1. Open General journals. Choose New journal batch; select a batch name, template and default accounting period, and save the draft batch.
  2. Add journal lines. From the batch choose Add line. Enter a unique line number, posting account, period, posting date, document number, description, and either a debit or credit. Add dimensions when relevant. Ensure the posting date is inside an open, unlocked accounting period.
  3. Balance the batch. Add all required lines and confirm total debits equal total credits. A batch must have at least one valid line. Correct validation messages before posting.
  4. Post the batch. On the batch page choose Post batch. Posting validates the accounts, dates, dimensions, and balance again, then creates ledger entries together. Posted lines and entries are immutable.
  5. Correct a posted batch using a full reversal. Open the posted batch and choose Reverse entire batch. Provide the reversing batch name, an open period and posting date, and description; then post the reversal. The app preserves and links the original batch and creates equal-and-opposite lines with debit and credit sides swapped.
Posting is not an edit. Review company, date, accounts, document numbers, tax, dimensions, and debit/credit totals before posting. Do not attempt to change posted transactions; use the supported full-batch reversal workflow when correction is necessary.

Manual tax on a journal

Tax is entered on journal lines; it is not calculated automatically on sales or purchase documents. When preparing a line, select the tax code and enter its taxable base. The page displays the rate effective on the posting date and a calculated tax amount. The debit/credit side determines whether the mapped recoverable or liability account is used. Review the displayed amount and mapped account, then post a balanced batch.

Tax rates must be effective on the line's posting date. Tax calculation in the journal helper does not replace a review of your organization's tax policy and required rounding.

Review the posted result

Open General ledger entries to search posted entries by date range, account, or a document-number substring. Select an account name to open its activity view, which presents opening balances, activity for the selected dates, and the closing balance. From Trial balance, choose an As of date and select Run report. Debits and credits should reconcile; use account activity and entry inquiry to investigate differences.

Banking and reconciliation

Record receipts/payments and reconcile a statement

Bank transactions are recorded through balanced general-journal drafts and reconciled manually to statement lines.

  1. Open the bank account. In Banking & reconciliation, follow Receipts, payments and statements for the selected bank.
  2. Create a receipt or payment draft. Choose receipt for money received or clear the receipt option for a payment. Enter a unique document number for that bank, description, posting date, positive amount, open accounting period, and offset G/L account; choose Create draft journal.
  3. Review and post the linked journal. Follow its General journals link, verify the two balanced lines and signs, then choose Post batch. A receipt debits the bank and credits the offset account; a payment debits the offset account and credits the bank.
  4. Create a statement. Return to the bank activity page. Enter a unique statement reference, statement start/end dates, opening balance, and closing balance; choose Create statement.
  5. Add statement lines. Enter each bank transaction with a unique line reference, transaction date, description, and signed amount. Receipts are positive; payments are negative. Alternatively paste tab-separated rows with no header in the format yyyy-MM-dd[TAB]reference[TAB]description[TAB]signed amount. Imports are all-or-nothing, limited to 1,000 lines, and reject duplicate references.
  6. Match each line manually. Select the exact signed-amount posted bank entry offered for that line, then choose Match. Matching is one-to-one; drafts, wrong-sign/amount entries, other companies/banks, and already-matched entries cannot be selected.
  7. Check differences and complete. The screen shows statement arithmetic difference and statement-versus-G/L closing difference. Correct header/line issues until statement arithmetic is zero and every statement line is matched, then choose Complete reconciliation. The completed statement and its matches are locked.
Understand the two balances. Statement arithmetic is closing balance minus opening balance minus statement lines; it must be zero to complete. Unmatched earlier posted book activity can remain as a visible timing difference. The app does not create adjusting entries automatically.
Banking scope: base currency only. Online bank feeds, stored banking credentials, payment initiation, automatic matching/reconciliation, checks, and foreign exchange are not included.

Reports, checklist, and scope

Review results and finish the workflow

  • General ledger entries: Find posted transactions with date, account, or document filters. Check account, posting date, document number, description, and debit/credit side.
  • Account activity: Review one account over a selected date range. Opening balance plus period activity should equal the closing balance.
  • Trial balance: Review posting-account debit/credit balances through an as-of date. Total debits should equal total credits; investigate any displayed difference.
  • Bank activity: Review a bank's receipts, payments, statements, and posted account activity. Check the bank closing balance and any unreconciled items or timing differences.
  • Statement reconciliation: Match statement lines to posted bank ledger entries. All statement lines must be matched and statement arithmetic difference must be zero before completion.

Suggested close-out checklist

  • Confirm the active company shown in the navigation is the intended company.
  • Confirm the company's base currency, chart of accounts, open accounting periods, and any needed dimensions/tax mappings.
  • Review each journal draft and confirm it balances before posting.
  • Verify posted entries, account activity, and trial-balance totals for the correct date range.
  • For each bank statement, reconcile every line and review both displayed differences before completing.
  • Sign out when you have finished using the application.

What is not in Phases 0-2

  • Sales and purchasing document lifecycles, invoicing, and automatic document tax calculation (planned for later work).
  • Inventory workflows, bank integrations/feeds, payment initiation, automatic reconciliation, foreign exchange, and check printing.
  • Public self-registration, user/company administration screens, and hosted production deployment.
  • General-purpose report export/download is not documented here; use the on-screen inquiry and report views currently available.
